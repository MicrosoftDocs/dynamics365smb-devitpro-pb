Use asynchronous processing to run AL code without making users wait for a batch to finish. You can also split independent work into smaller tasks and run them in parallel.

Choose a mechanism based on the work you need to run and its lifetime. The following table also identifies the main Business Central online limits.

| Mechanism | Characteristics | Main Business Central online limits |
|-----------|-----------------|-------------------------------------|
| [Page background task](../developer/devenv-page-background-tasks.md) | Read-only database access in a child session tied to the calling page and parent session. Canceled if the page or parent session closes, the current record changes, or the task times out. Can also be canceled explicitly. | [Child session concurrency and queue length; page background task timeouts](../administration/operational-limits-online.md#Task) |
| [Session.StartSession](../developer/methods-auto/session/session-startsession-integer-integer-string-table-method.md) | Creates a background session on the same Business Central Server instance when called. Codeunit execution can wait in the background-session queue. Not tied to a page or the lifetime of the calling session. Can write to the database, subject to permissions. Subject to background-session queueing and timeout controls. | [Background session concurrency, queue length, and waiting timeout](../administration/operational-limits-online.md#Task) |
| [Task scheduler](../developer/devenv-task-scheduler.md) | Stores a task for execution when it's ready and its earliest start time has passed. Runs in a background session on an eligible server instance in the cluster. Tasks are persisted in the database and recoverable after server restarts. Monitor execution through task scheduler telemetry and session events. | [Scheduled task concurrency](../administration/operational-limits-online.md#TaskUser) |
| [Job queue](../developer/devenv-job-queue.md) | Supports one-time and recurring schedules. Uses the task scheduler to run in a background session on an eligible server instance. Uses persisted job queue entries and scheduled tasks, with restart recovery. Records execution status and error details in **Job Queue Log Entries**. | [Scheduled task concurrency, shared with other scheduled tasks](../administration/operational-limits-online.md#TaskUser) |

For scheduled tasks, the server instance must have task scheduling enabled and serve the tenant. Restart recovery can rerun work; it doesn't resume execution at the interrupted instruction.
