# Run cloud migration setup

This article explains how to run the **Cloud Migration Setup** assisted setup guide to configure the components and connection for migrating data from a Business Central on-premises database to Business Central online environment. To learn more about the mechanics behind the **Cloud Migration Setup**, go to [Cloud migration setup overview](migration-setup-overview.md).

## About delegated administrators

Any user running the cloud migration setup flow as a delegated administrator must receive approval from a licensed user in order to run the cloud migration. The licensed user must have the *Essentials* or the *Premium* license and **SUPER** permissions. In this case, the **Cloud Migration Setup** assisted setup guide displays an extra step, where the delegated administrator can copy the autogenerated approval link and send it to the licensed user for approval. Once the licensed user has approved the request, the delegated administrator must restart the setup guide to continue. The licensed user can revoke the permission by opening the same approval link or the **Delegated admin consent for cloud migration** page and selecting **Revoke Consent**. Revoking consent stops the cloud migration.

## Run the cloud migration setup

<!--Does it matter what machine you run the setup, repl, from? If this is the first time running cloud setup should you run it on the machine where SQL db is so IR install?-->

1. [Sign in to the Microsoft 365 tenant](https://admin.microsoft.com) used by [!INCLUDE [prod_short](../includes/prod_short.md)] online.

   The person who sets up and runs the cloud migration must be signed in as an administrator of the Microsoft Entra (Microsoft 365) tenant and [!INCLUDE [prod_short](../includes/prod_short.md)] online.
1. [Sign in to Business Central online](https://businesscentral.dynamics.com) and open the environment that you want to migrate the data to.
1. [!INCLUDE [open-search](../developer/includes/open-search.md)], enter **Cloud Migration Setup**, and then select the related link.
1. Read the information on the page and provided links. If you consent, switch on **I accept warning & privacy notice**, then select **Next**.
1. Set **Product** option to the version that matches the on-premises product that you're migrating, then select **Next**.

   Select the current-version option only if the source and destination use the same major version. Select the earlier-versions option if the source uses an earlier supported major version.
1. On the **Define your SQL database connection** page, fill in the information about the SQL database connection and integration runtime.

   Learn more in [Define your SQL database connection](#define-sql-database-connection-and-integration-runtime).

   Select **Next** when done. Once you choose **Next**, a new pipeline is created in the Azure service. When completed successfully, the **Select companies to migrate** page appears.

    <!-- bc 1. On the **Select companies to migrate** page, select one or more companies from the list or switch on **All Companies**, then select **Next**.-->

1. On the **Select companies to migrate** page, select one or more companies to migrate or, if available, switch on **Migrate all companies**, then select **Next**.

   You can always return to the page to add more companies.

1. Select **Finish** to complete the cloud migration setup.

   If you want to open **Cloud Migration Management**, where you can run the migration, select **Yes**.

## Rerunning cloud migration setup guide

There are some scenarios where it may be necessary for you to run the cloud migration setup guide more than once.  

> [!TIP]
> Before changing the setup, review how to restore the target environment to a specific point in time. Learn more in [Restoring an environment](tenant-admin-center-backup-restore.md).

The following list highlights a few examples:

- Multiple companies in [!INCLUDE [prod_short](../includes/prod_short.md)] on-premises

  One example is if you want to add more companies to the migration, or if you want to change the companies to migrate, run the assisted setup guide again. A more efficient option, though, is to use the **Select Companies to Migrate** action from the **Cloud Migration Management** page.  

- Add tenants to an existing runtime service  

  If you're a hosting partner, you may have multiple tenants running on the same integration runtime service. Each tenant is isolated in its own data pipeline. To add tenants to an existing integration runtime service, enter the name of the existing integration runtime service into this field. The integration runtime name can be found in the Microsoft Integration Runtime Configuration Manager. Learn more in [Create and configure a self-hosted integration runtime](/azure/data-factory/create-self-hosted-integration-runtime).

In both examples, you're making updates to an existing runtime service. When the assisted setup guide asks for an existing runtime service name, open the Microsoft Integration Runtime Configuration Manager to find the name. Enter that name in the **Integration Runtime Name** field to reuse the existing service rather than create a new one.

Complete the steps in the wizard to update the runtime service. If the change was related to adding tenants to an existing service, a new data pipeline is created for that tenant. You can regenerate an Azure Data Factory key from the **Cloud Migration Management** page in [!INCLUDE[prod_short](../developer/includes/prod_short.md)] online. Learn more in [Manage cloud migration](migration-manage.md).

> [!TIP]
> If you're using [!INCLUDE[prod_short](../developer/includes/prod_short.md)] on-premises, the same setup guide is also available in your on-premises solution. You'll automatically be redirected to [!INCLUDE[prod_short](../developer/includes/prod_short.md)] online to continue the configuration process.

> [!CAUTION]
> If you have mapped users in the first run of the cloud migration setup guide, then do not choose the **Define User Mappings** action again in subsequent runs.
