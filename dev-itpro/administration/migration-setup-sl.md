# Run cloud migration setup for Dynamics SL migration

This article explains how to run the **Cloud Migration Setup** guide to configure the components and connection for migrating data from a Dynamics SL on-premises database to a Business Central online environment. Learn more in [Cloud migration setup overview](migration-setup-overview.md).

[!INCLUDE [migrate-e2e-process](../developer/includes/migrate-e2e-process-sl.md)]

## About delegated administrators

Any user running the cloud migration setup flow as a delegated administrator must get approval from a licensed user to run cloud migration. The licensed user must have an Essentials or Premium license and the **SUPER** permission set. The setup guide displays an extra step where the delegated administrator can copy the autogenerated approval link and send it to the licensed user. After approval, the delegated administrator must restart the setup guide. The licensed user can revoke consent by opening the same link or the **Delegated admin consent for cloud migration** page and selecting **Revoke Consent**. Revoking consent stops cloud migration.

## Prepare for migration setup

- Review [Cloud migration prerequisites for Dynamics SL](cloud-migration-prerequisites-sl.md) and make sure the environments meet the requirements. You must have the **SUPER** permission set in Business Central.

   > [!IMPORTANT]
   > [!INCLUDE [bc-cloud-migrate-prod](../includes/bc-cloud-migrate-prod.md)]

- Review existing users' access to the target companies. Dynamics SL migration retains existing Business Central permissions rather than automatically assigning a read-only permission set. Restrict data entry until migration is complete.

> [!TIP]
> Run the assisted setup from a company that you aren't migrating. The guide prevents you from selecting your current company for migration. For example, sign in to the demonstration company, CRONUS, and start the process there.
>
> Be aware of the storage capacity of your online tenant. If you need more than your included capacity, you can buy additional environments or storage capacity. Storage capacity is 80 GB plus allowances per licensed Essentials/Premium user and any storage capacity licenses. Learn more in [Managing capacity](tenant-admin-center-capacity.md).

## Run the cloud migration setup

1. [Sign in to Business Central online](https://businesscentral.dynamics.com) and open the environment to which you're migrating the data.
1. Search for and open the **Cloud Migration Setup** assisted setup guide.
1. Read the information on the page and provided links. If you consent, switch on **I accept warning & privacy notice**, then select **Next**.
1. Set **Product** to **Dynamics SL**, then select **Next**.
1. On the **Define your SQL database connection** page, fill in the information about the SQL database connection and integration runtime.

   Learn more in [Define SQL database connection and integration runtime](#define-sql-database-connection-and-integration-runtime).

   Select **Next** when done. Once you choose **Next**, a new pipeline is created in the Azure service.

1. After the pipeline is created, the **Select companies to migrate** page appears. Select one or more companies from the list, or turn on **Migrate all companies** when that option is available, then select **Next**.

1. Select **Finish** to complete the setup guide and open the SL company migration configuration.
1. Configure the companies and data to migrate. Learn more in [Configure Dynamics SL company migration](migrate-sl-configure-companies.md).

## Rerunning cloud migration setup guide

There are some scenarios where it might be necessary for you to run the cloud migration setup guide more than once.  

> [!TIP]
> We recommend that you take a backup of the target environment so that you can easily restore the environment to a specific state and time, should you want to do so.

A common scenario is when you want to add tenants to an existing runtime service. If you're a hosting partner, you might have multiple tenants running on the same integration runtime service. Each tenant is isolated in their own data pipeline. To add tenants to an existing integration runtime service, enter the name of the existing integration runtime service into this field. The integration runtime name can be found in the **Microsoft Integration Runtime Manager**. Learn more in [Create and configure a self-hosted integration runtime](/azure/data-factory/create-self-hosted-integration-runtime) in the Azure docs.

In this scenario, you're making updates to an existing runtime service. When the assisted setup guide asks for an existing runtime, enter its name in **Integration Runtime Name**. The runtime service identifies that you're making updates to an existing service and doesn't create a new one.

Complete the steps in the wizard to update the runtime service. If the change is related to adding tenants to an existing service, a new data pipeline is created for that tenant. To regenerate the integration runtime keys, use **Reset runtime service key** on **Cloud Migration Management**.
